# Reference Asset Library（可持久化参考资产库）

## Goal

实现可持久化参考资产库，复用现有画廊集合（`gallery_collections`）作为资产包/角色包，允许用户在图像编辑链路和 Agent 交互链路中一键引用整套有序参考图，并在多轮与多设备间保持持久与一致。

整体方案按 5 个阶段稳健推进：
- **阶段 1：数据与资产 API**（数据库迁移、别名与重排、参考条目有序读取接口）
- **阶段 2：编辑链路支持多张画廊参考**（后端接受多张 `reference_image_id`，前端支持画廊引用集合，保持固定顺序与掩码）
- **阶段 3：选图器与资产管理**（从资产包一键添加、集合管理资产包别名与上下移改序）
- **阶段 4：Agent `@资产包`**（输入框 `@别名` 提示与解析、后端事务内展开普通 input 行与分配标签、模型提示词增强）
- **阶段 5：持久化补强与文档**（归档导出导入包含资产包别名与顺序映射、更新规格与文档）

## Requirements

1. **资产包定义与存储**：
   - 复用 `gallery_collections`，不侵入 `gallery_entries`，不使用纯前端 localStorage。
   - 集合增加可选的 `asset_alias`（字符集 `[\p{L}\p{N}_-]`，长度 1–32，大小写不敏感唯一）。非空即为资产包，空表示普通集合。
   - 集合成员（`gallery_collection_items`）支持有序存储 `position`，排序规则统一为：`ORDER BY position IS NULL, position, added_at, image_id`。

2. **编辑链路参考图能力**：
   - 扩充编辑接口，支持提交多张画廊参考图（`reference_image_id`），与主图、上传图合计上限 16 张。
   - 顺序语义严格固定为：`[路径画廊主图?, *uploads, *reference_image_id]`，确保掩码/markup 作用于第一张主图，避免因注入资产破坏掩码。
   - 后端在暂存前进行总数校验，过滤并拒绝 SVG/GIF 输入。

3. **选图器与集合管理**：
   - 编辑器增加“从资产包添加”弹窗，提供按张勾选及容量截断提示。
   - 集合管理弹窗支持设置/清除别名，以及通过上移/下移调整成员顺序。

4. **Agent 对话 `@资产包` 展开**：
   - 用户消息中支持 `@别名`，请求提交显式附件 `{kind: "asset", collection_id}`。
   - 后端 `create_turn` 在同一事务内按序将资产包展开为普通 input 行，分配 `round-N-input-K` 标签，分组写入用户消息块 `asset_refs`。
   - 上下文格式化仅输出紧凑的一行 `[asset @alias: <ref ...>]`，保持历史快照稳定。

5. **归档与导入恢复**：
   - 归档导出在 `metadata.json` 中保留资产包结构与有序成员。
   - 导入时按 ID 映射恢复资产包，遇同名/别名冲突时自动添加后缀避免覆盖。

## Acceptance Criteria

- [ ] 阶段 1：集合表新增 `asset_alias`，条目表新增 `position`；别名具备唯一性与格式校验；提供别名更新、按序获取可用参考图（排除 SVG/GIF）、成员重排接口。
- [ ] 阶段 2：编辑链路支持多张 `reference_image_id`；后端在暂存前校验 ≤ 16 张；前端编辑源状态支持画廊引用列表；组合顺序与掩码保留验证通过。
- [ ] 阶段 3：前端提供资产包选图器，支持一键注入与槽位截断提示；集合管理支持资产包别名设置与成员上移/下移。
- [ ] 阶段 4：Agent 输入支持 `@别名` 联想与派生 chip；后端正确展开资产并记录快照；模型上下文正确引用；分支与重新生成稳定。
- [ ] 阶段 5：图库导出导入完整保留资产包；完成全套契约测试、E2E 测试与规范文档更新。
