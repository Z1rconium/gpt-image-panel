> 状态：Phase 0–5 已完成代码落地，2026-10-02 补齐核查发现的缺口；自动化证据与人工验证边界见第 14 节。Phase 6–7 尚未实施。

## 1. 目标与现状

优先解决异步任务恢复中的重复提交风险，扩展通用供应商协议，然后改善配置、诊断、图片预览和图库操作，最后完成 Agent 分支与联网搜索。

以下能力已经存在，实施时应复用：

- Agent 多轮对话、关联图片批量生成、依赖轮次、`@` 图片引用、服务端历史和 SSE 续传。
- Gallery 多收藏夹、排序、默认收藏夹、跨页选择、筛选结果全选、收藏夹 ZIP 导出。
- 原生透明背景、色键去背、提示词防改写、参数追踪、尺寸预设、任务费用统计。
- API 预设管理与健康检查；“新建预设”会复制当前预设；URL 支持 `apiUrl`、`apiModel` 预填。
- 生成/编辑共享的图片任务单元、租约、claim token、取消、重试、Webhook、蒙版持久化及结果回贴。

需要补强的关键现状：

- 自定义异步供应商在单次调用中持有远端状态；远端任务 ID/查询 URL 尚未持久化，租约过期后重新提交。
- 当前映射仅覆盖异步 JSON 文生图，查询地址须由上游响应提供；缺少 task_id 拼接查询路径、同步接口和自定义编辑协议。
- 图片中间预览仅开放单图 Images 生成/编辑；Agent 文字流式回复已经存在，Responses 中间图片预览尚未接入。
- Agent 会话是线性的；回复文本尚未提供 Markdown 渲染、搜索过程与结构化来源引用。
- 图库已有批量能力和收藏夹封面 ID，但缺少框选、移动端快捷选择和收藏夹封面概览入口。

## 5. Phase 1：异步任务持久化与恢复

覆盖：R01、R02。优先解决已提交任务在 worker 切换后重新生成的问题。

### 工作内容

1. 为每个 image_job_unit 持久化远端检查点：任务 ID、状态/结果/取消 URL、提交阶段、提交时间、绝对截止时间，以及执行所需的非密钥映射快照和上游 origin。凭据沿用现有预设解析机制。
2. 将“提交任务”和“查询任务”拆成可恢复步骤。收到提交响应后，用当前 claim token 条件写入检查点，再进入轮询。
3. worker 接管已有检查点的任务时直接继续查询。重新启动不会重置截止时间，也不会把一次恢复算作一次新的上游生成。
4. 支持从响应提取 task_id，再渲染查询路径；现有响应直接返回 URL 的形式继续可用。结果与取消地址支持同样的通用构造方式。建议在本阶段引入 provider_config v2 的最小契约，v1 归一后继续执行；阶段 3 在 v2 中增加可选协议能力。
5. 所有构造/恢复出的 URL 都沿用同源、SSRF、peer-IP 和凭据发送边界；ID 作为路径参数编码，不拼接任意完整地址。
6. 明确区分主动取消、任务超时、暂时网络故障和租约丢失。丢失所有权的 worker 停止本地操作，由新 owner 接管；不能因为本地租约丢失就取消新 owner 正在查询的远端任务。
7. 结果入库按任务单元与结果序号建立幂等关系。重放查询、下载或提交最终状态不会新增重复 Gallery 记录；文件写入中断沿用原子写入与孤儿文件清理机制。
8. 调整接管次数与现有 attempts 上限的关系：恢复应受独立次数/截止时间约束，不能因轮询接管直接触发重新提交；限制仍须防止无限恢复。

### 提交结果不确定时的处理

上游已接收请求、但客户端尚未拿到或保存响应，是无法仅靠本地事务消除的时间窗口。计划中的恢复机制不承诺跨系统 exactly-once。

- 上游支持幂等键时，为同一任务单元持久化并复用稳定键。
- 上游支持按客户端请求标识查询时，先尝试找回远端任务。
- 两者均不支持且提交结果未知时，使用明确的 interrupted/诊断状态，要求用户显式发起新任务；不自动重复提交。
- 已知任务返回 404、凭据失效或结果过期时，显示具体恢复失败原因，不自动新建付费请求。
- 升级前尚未开始提交的 queued 任务正常执行；旧 running 任务缺少检查点时按提交结果未知处理，不能用“没有检查点”推断上游没有接收请求。

### 验收标准

- [x] 在远端返回任务信息后强制终止 worker，接管后上游 submit 次数仍为 1，结果成功保存。
- [x] 两个 worker 竞争恢复时，只有当前 owner 能更新检查点与终态；图库结果不会重复。
- [x] worker 丢失租约不会错误取消远端任务；用户主动取消会阻止恢复并发送尽力而为的远端取消。

## 6. Phase 2：配置迁移、编写辅助与诊断

覆盖：R05、R06、R07。让复杂映射容易建立、迁移和排查。

### 配置导入导出与排序

1. 定义带格式版本的导出包，覆盖预设名称、地址、模型、API 路径、参数行为和 provider_config；凭据、代理密码及其他 secret 值不写入导出包。
2. 提供 JSON 文件/剪贴板导入、选定预设导出和无密钥分享链接。链接只携带有大小限制的内联配置，保留现有 `apiUrl`/`apiModel` 预填。
3. 导入先展示预览：新增项、重名项、映射错误、缺少凭据的项；默认创建新预设，更新现有预设须由用户明确选择，失败时不留下半套配置。
4. 链接解析后立即移除地址栏参数；校验前不写入存储、不切换当前预设、不发起上游请求。分享地址可携带模型和接口信息，内容应可在导入预览中检查。
5. 增加预设持久化排序，提供拖拽及键盘/按钮操作；已有复制行为保留，并使入口文案更明确。
6. 拟新增接口：选定预设导出、导入预览、导入应用、预设顺序更新。静态路径需先于预设 ID 路由注册，响应只能返回允许导出的字段。

### 映射编写辅助

1. 设置中增加“复制映射生成提示词”，附上本项目的 schema、变量、JSONPath 子集、凭据规则和中性示例。
2. 提示词要求根据用户提供的 API 文档生成映射，并明确不索要 API Key；缺少接口信息时应列出缺口。
3. 提供实时 JSON/字段/路径/变量校验，以及粘贴模拟响应后验证任务 ID、状态和结果提取的入口。支持显示字段路径级错误，不只显示“JSON 无效”。
4. 本阶段先支持 v1 和阶段 1 新契约；阶段 3 扩展协议后同步更新提示词、校验和示例。
5. 可提供请求结构预览；该预览不调用生图接口，不把凭据展开到页面。

### 失败响应与参数诊断

1. 在现有 ImageTrace 和任务详情中增加受限的诊断视图：请求参数摘要、HTTP 状态、提交/查询/下载阶段、响应结构及失败的映射路径。
2. 展示经过脱敏、限长和二进制省略的响应快照。优先保留失败任务；建议单任务单元上限 64 KiB，并与现有任务历史清理生命周期一致。
3. 去除密钥、Authorization、带凭据 URL、图片 base64、巨大数组及签名下载 URL 中的敏感部分；将省略字段和截断原因明确显示。
4. 提供“复制诊断信息”，便于复现映射错误；继续使用现有诊断码，新增码需区分提交结果未知、无法提取任务 ID、轮询超时和结果提取失败等情况。
5. 参数追踪补充请求值与实际值的差异突出显示，并区分“上游未报告”和“明确不一致”。数据缺失时不推断模型忽略了参数。

- 恢复语义：接管时已持有 `submitted` 检查点则直接续查，不重新提交；`submitting` 阶段仅在存在已持久化幂等键时允许用同一键重投，否则以 `interrupted` + `submit_unknown` 诊断终止且不自动重试；`results_ready` 检查点可让新 owner 只重放终态写入。接管次数由模块常量 `IMAGE_JOB_UNIT_MAX_RECOVERIES = 5`（`core/constants.py`）独立约束，attempts 上限只约束真正的新生成。
- 供应商协议：`provider_config` 新增 v2（`version: 2`）：`poll.task_id_path` + `url_template`（`result`/`cancel` 同构）与可选 `submit.idempotency_header`；模板按纯路径校验，任务 ID 以路径段编码；v1 与缺省 version 的配置继续按 v1 解析。

- 结果幂等：图库结果 ID 由 `uuid5(unit_id, result_index)` 生成，重放查询/下载/终态写入只 upsert 同一行。
