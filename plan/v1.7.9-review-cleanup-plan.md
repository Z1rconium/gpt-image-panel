# v1.7.0–v1.7.8 review: fixes and cleanup plan

> Created: 2026-10-05. Baseline: `v1.7.8` (`a6c6265`), compared with `v1.6.3`.
> Update the checkboxes as phases land; add the release in which each item shipped.

## Review summary

No high-severity vulnerability was found. The review covered the async provider
engine, body limiting, redaction, diagnostics, SSRF/origin checks, preset
import, Agent routes/tools/refs, Markdown and citation rendering, and the
dependency changes. `agent_turns.py`, `repositories/agent.py` and the
Lightbox/gallery gesture code were only skimmed.

Baseline before any change: `svelte-check` 0 errors, 182 frontend unit tests,
866 backend tests passing (22 skipped). `test_full_image_decode_runs_off_event_loop`
failed once inside the full run but passes alone (timing-sensitive under load).

## Phases

- [x] **Phase 1 — correctness (shipped in v1.7.9):** #1, #2, #3, each with a test.
- [x] **Phase 2 — dead code (shipped in v1.7.9):** #4, #5, #6, #12 (the first-item special case), plus a Lint workflow (`.github/workflows/lint.yml`) for unused imports/variables on the cleaned files. Other pre-existing unused imports (e.g. the `repositories/db` re-export facades, `assistant_runtime.py`) were left because tests or callers may patch them.
- [x] **Phase 3 — security hardening (shipped in v1.7.10):** #7 (the `?apiUrl=` banner now shows the target host prominently with a trust warning), #8 (GET/HEAD/OPTIONS skip the route scan; `/api/import` etc. match whole path segments), #9 (`UPSTREAM_USER_AGENT`, default `opencode`).
- [x] **Phase 4 — behavior-preserving refactor (shipped in v1.7.10):** #10 done: `run_async_provider` is now a ~90-line coordinator over `_resume_remote_task` / `_submit_task` / `_poll_until_done` / `_fetch_result_items`, with one `_backoff_sleep` helper and one `_resolve_mapped_url` resolver for the result/cancel URLs (the status URL keeps its own resolver because it validates after appending the query). The existing recovery, SSRF and diagnostics contract tests pass unchanged. #11 was intentionally left: `run_claimed_image_unit`, `create_turn` and the generation/edit API pair are large and not covered tightly enough to refactor without risk to paid-request semantics; revisit with characterization tests first.
- [x] **Phase 5 — release hygiene (v1.7.10):** CHANGELOG, VERSION, `docker-compose.yml` image tag for each release; full backend suite, `svelte-check`, frontend unit tests and the Agent/Settings browser tests.

## Not covered

Real-provider and physical touch-device checks (manual validation per the
CHANGELOG), and a deep review of `agent_turns.py`, `repositories/agent.py` and
the Lightbox/gallery gesture code.
