# Changelog

## v1.7.6

- Streaming previews now support the Responses image-generation tool and batches of 1–10 queued units. Per-unit/output-call slots retain independent previews and final images; terminal unit statuses prevent delayed frames from returning. Responses output completion, response completion/failure, malformed SSE, cancellation and JSON final responses are handled without automatic paid resubmission; usage is recorded once per response.
- Slow preview subscribers retain one latest frame per slot. Preview data remains process-local and bounded; terminal units and jobs release cached frames. Migration 36 adds parent unit statuses and Agent ownership (`unit_statuses_json`, `agent_turn_id`, `agent_conversation_id`) while preserving old jobs.
- Queued generation and edit tasks freeze non-secret provider settings before execution. Credentials remain live; a changed API origin explicitly fails the task. Existing remote checkpoints and provider_config v1/v2 recovery continue to apply.
- Gallery gains desktop rectangle/modifier selection, deliberate horizontal touch selection and a collection overview with batched cover filenames. Vertical scrolling remains available, one swipe toggles once, and filtered selection tokens survive card gestures and page-selection attempts.
- Lightbox supports pinch zoom, enlarged panning, double tap and long-press download/favorite/edit actions, including single-image galleries. Gesture state resets between images; Escape closes the action menu first.
- Browser completion notifications are opt-in and require supported secure-context browsers. Background completion is summarized once per parent image task or Agent turn; Agent child jobs do not create separate notices. Bounded shared history and Web Locks coordinate tabs/replays, permission denial leaves the preference off, and clicking a notice opens its result or conversation.
- Updated English, Simplified Chinese and Traditional Chinese documentation, the Phase 0–5 audit and regression coverage. Added a reproducible synthetic preview-retention benchmark; frontend budget changes record measured increments. Real-provider and physical touch-device checks remain separate manual validation.

## v1.7.5

- Generic provider protocol (phase 3): v2 mappings gain `"mode": "sync"` (submit response carries the images directly; `poll`/`cancel` omitted) alongside the full async task flow, `submit.method`/`poll.method` with GET/POST whitelists, and query-parameter templates (`submit.query`/`edit_submit.query` from the submit variables, `poll.query` from `{{task_id}}`). A GET submit must have an empty body; a POST poll sends an empty JSON object.
- Provider image edits: an `edit_submit` section declares edit capability. Multipart edits stream the panel's validated reference images and mask as file parts (`files.images`/`files.mask`); JSON edits inline `{{reference_images}}` (bounded data-URL list, 24 MiB decoded budget) and `{{mask}}`. Edits reuse upload validation, mask preprocessing, cancellation, source reservation and result paste-back; a mapping that cannot carry a provided mask is rejected before submit instead of silently dropping it.
- Provider capabilities: the mapping's shape is resolved into one capability view (`generate`, `edit`, `mask`, `stream`, `transparent_background`, `formats`) shared by queue admission and the UI. `background: transparent` and undeclared output formats are refused before submit with a clear reason (`capabilities.transparent_background`/`capabilities.formats` declare support; transparent auto-detects from `{{background}}` usage); `stream` stays reserved. Chroma backgrounds are now available for mapped generation (the provider receives the opaque background and keyed prompt; the panel keys the color locally). `supports_mask` for async presets follows the mapping's mask capability, so the mask editor appears only when the mask reaches the provider. Settings responses publish `provider_capabilities` per preset, the mapping validator returns the resolved set, and the prompt/placeholder/docs cover the new fields.
- Running tasks keep the mapping snapshot taken at submit (now also for sync and edit submits), so editing a preset's `provider_config` never changes what an in-flight or recovered task sends.

## v1.7.3

- Custom async providers: an API preset can now use `provider_kind: async_json` with a declarative `provider_config` JSON mapping (submit → poll → fetch result) instead of the OpenAI paths. No specific provider is built in; the Settings editor shows a neutral skeleton and the README documents every field. Request bodies use a fixed set of `{{placeholders}}` (fields whose variable has no value, such as `width` for size `auto`, are omitted) and responses are read with a small JSONPath subset; nothing is evaluated as code.
- The mapping never holds credentials: the preset's API key is sent as `header: scheme key` (`Authorization` or `X-API-Key`; `Bearer`, `Key`, `Token` or none). Status, result and cancel URLs come from upstream responses and must share the preset API URL's origin and pass the SSRF and peer-IP checks; images are downloaded without credentials and errors are redacted. Timeouts and cancellation send a best-effort remote cancel.
- Async providers do not support image edits, streaming previews or local chroma removal (rejected at admission with a clear error), and masks are forced off. A lease that expires mid-task resubmits the task because the remote task id is not persisted. The preset health check validates the mapping and probes the submit URL without submitting a task. The engine is covered by fake-session tests only.
- Migration 33 adds `provider_kind` (default `openai`) and a nullable `provider_config` to `api_presets`; existing presets are unchanged.
- URL quick fill: opening `/?apiUrl=https://…&apiModel=…` offers to create a new preset with that URL and model. Nothing is saved until the user confirms, the API key stays empty, and the parameters are removed from the address bar immediately. Only `https` URLs are accepted, credentials are never read from the URL, and the parameter is `apiModel` because `?model=` is the gallery filter.

## v1.7.2

- Agent turn admission now reserves capacity before database waits, including pending creates in the per-worker `AGENT_MAX_ACTIVE_TURNS` limit. Idempotent replays remain available at capacity, and request cancellation completes admission so queued turns receive a runner.
- Assistant slot acquisition uses one deadline for local semaphore waits, SQLite attempts and retries. Late leases are released after timeout or cancellation; the deadline does not shorten an admitted model request.
- JSON body limits follow registered route declarations even with absent or incorrect Content-Type, including chunked bodies rejected before parsing with 413. Agent `after` cursors must fit a nonnegative SQLite 64-bit integer (422 otherwise); invalid or non-ASCII Last-Event-ID values are ignored and synthetic terminal cursors cannot overflow.
- Stale-turn cleanup rechecks expiration inside its write transaction. Lost or expired execution leases stop the Agent and fence business writes; interruption, cancellation, shutdown and failures clean up pending jobs and edit-source staging files while preserving established terminal states and gallery images. Text snapshots track modification versions and retry failed writes without losing changes made during persistence.
- Vision previews use the bounded image/file executors and a separate strict `VISION_PREVIEW_MEMORY_BUDGET_MB` budget (256 MiB per process by default, range 32–16384, configurable in Overall Config). Estimates use decoded pixels × 16 plus three preview byte limits, with JPEG draft dimensions. Oversized Agent previews are skipped without removing text references or original images; direct Assistant analysis returns 400 if a preview cannot fit.
- Preview loading uses an ordered window of at most three items and stops scheduling at byte/image limits; tool results load at most four successful previews. Concurrent cache misses share a decode unaffected by caller cancellation. Cache keys include file state and all preview safety settings; clear operations fence older fills, and the 32-entry / 15-minute / 24-MiB LRU accounts for retained data-URL string memory, expires old entries and does not cache oversized entries.
- Added resource/cache counters and gauges, boundary regressions, and reproducible cold/hot/shared/distinct preview benchmarks. See `VISION_PREVIEW_PERFORMANCE.md` for commands, measurements and interpretation. No SQLite migration is required.

## v1.7.1

- Security hardening for Agent mode: message text and attachments are validated against the configured limits in the request schema, oversized Last-Event-ID cursors are ignored instead of raising, edit-source temp files only reuse known image suffixes, and the startup sweep no longer deletes staging files a running turn may still use. All `AGENT_*` overall-config overrides now have upper bounds.
- Agent runner reliability: tool calls per model round are capped, a saturated AI Assistant concurrency pool fails the turn after a bounded wait instead of holding it open, background tasks are awaited on turn teardown, and the SSE tail closes cleanly on backend errors so the browser can reconnect.
- Agent performance: turn events are written in batches with caller-owned sequence numbers, block snapshots persist on the existing 1s cadence, idle stale-turn sweeps no longer take the write lock, and migration 32 adds image-order, pending-image and finished-turn indexes. Vision previews are cached in-process (bounded LRU) and loaded concurrently, the model request body is serialized off the event loop, and conversation detail only returns image references for the messages in the page.
- Agent web UI: returning to a tab resumes the event stream from the last applied event instead of replaying the turn, cancel leaves the "stopping" state through a status-poll fallback, stream frames paint once per animation frame, recovery attempts reset per conversation, and an abandoned reply is marked interrupted.

## v1.7.0

- Agent conversation mode: a Studio/Agent switch in the header opens a multi-turn chat in which the model plans and creates images. Enable it under Settings → AI Assistant; it reuses the Prompt Optimizer endpoint and needs a model that supports function calling (chat/completions or responses).
- The Agent calls `generate_image_batch` (independent images run concurrently) and `continue_generation` (a later round for images that depend on earlier ones). Every image goes through the normal job queue, so presets, keys, concurrency limits, cost tracking, webhooks, and the gallery all apply. Referencing an earlier image with `@round-N-image-M` (or `@第N轮图M`) edits it instead of generating from scratch.
- Conversations, turns, messages, and image references are stored in SQLite (migration 31). Turns run in the background and record replayable events, so a reload, a second tab, or another worker can follow a reply (`GET /api/agent/turns/{id}/events`, resumable with `?after=` or `Last-Event-ID`). Stop cancels the turn and its queued image jobs; a turn whose worker died is marked interrupted.
- Deleting a conversation keeps its gallery images. Deleting a gallery image marks it as deleted in the conversation and hides it from `@` suggestions.
- New `AGENT_*` limits (also in Overall Config and `.env.example`) cap conversations, turns, message and prompt length, attachments, images per batch and per turn, history images, tool rounds, and concurrent turns.
- The main stylesheet budget in `bundle-budget.mjs` is raised from 12.9 to 13.3 KiB for the new view's utility classes.

## Unreleased

- Mask edge smoothing now only adds editable pixels; it never removes a painted area.
- Automatic gap filling is enabled by default in the mask editor. The added area is visible in the preview and coverage readout.
- Imported soft alpha masks treat pixels with alpha below 128 as editable. Black and white masks use white as the editable area; same-ratio masks can be scaled on import.
- Masked edits paste the model result back onto the primary image by default. The final result reports whether paste-back was applied or why it was skipped; the switch can be turned off for each edit.
- The preview of a masked edit can switch between the final result and the primary image used for that request.
- The paste-back drift guard now compares red, green, and blue separately, so a color shift that leaves luminance unchanged is also caught.
- Async provider recovery: image job units now persist a remote checkpoint (task id, status/result/cancel URLs, submit phase, absolute poll deadline, idempotency key, mapping snapshot and upstream origin) under the unit's claim fence. A recovered unit resumes polling instead of submitting the task again, the poll deadline survives restarts, and takeover retries are bounded by an independent recovery count (default 5) rather than the generation attempt limit. A submit whose result was never recorded is marked `interrupted` with a `submit_unknown` diagnostic and is never resubmitted automatically; an upstream that accepts an idempotency header can be re-submitted under the same stable key. Lease loss no longer cancels the remote task; user cancellation still sends a best-effort remote cancel. Transient poll failures (429/5xx/network) back off within the deadline, while 4xx terminal errors fail the unit immediately. Migration 34 adds `remote_json`, `checkpointed` and `recovery_count` to `image_job_units`.
- Result idempotency: gallery results are identified by unit + result index (`uuid5`), so replaying a query, download or terminal write upserts the same row; a `results_ready` checkpoint lets a recovered worker finish the terminal write without touching upstream again.
- Provider mapping v2 (minimal contract for this phase): `version: 2` adds `poll.task_id_path` with `url_template` (and the same for result/cancel), rendered as a plain path with the task id percent-encoded as one segment, plus optional `submit.idempotency_header`. Version 1 mappings continue to work unchanged; mappings without a `version` still parse as v1.
- Mapping authoring assistance: Settings exposes “Copy mapping prompt” (a versioned prompt describing the schema, variables, JSONPath subset and credential rules) and live validation of the pasted mapping with field-path errors. Pasting sample submit/poll/result responses verifies task-id, status and image extraction locally — no upstream request is made; previews are redacted and truncated.
- Preset import/export: export the selected preset as a versioned, secret-free JSON package, import one from a file or clipboard with a preview that lists duplicates, mapping errors and missing credentials, and share a preset as a `?preset=` base64url link (24 KiB decoded limit) that is parsed once and removed from the address bar. Import is atomic (validation happens before any write), defaults to creating new presets, and updating an existing preset (or reusing its API key) requires an explicit choice. New endpoints: `POST /api/settings/presets/export`, `POST /api/settings/presets/import/preview`, `POST /api/settings/presets/import`, and `PUT /api/settings/presets/order` for drag/keyboard preset ordering persisted in SQLite.
- Diagnostics: failed async units keep a bounded (64 KiB), redacted record of the submit/poll/result stages (HTTP status, redacted response snapshots, failed mapping path, truncation markers) in `image_job_units.diagnostics_json` (migration 35). Job history gains a Diagnostics panel with per-unit recovery state and a “Copy diagnostics” action; snapshot previews omit credentials, signed URL queries, image base64 and oversized arrays. Parameter tracing now labels API-reported size/quality as matching, differing, or not reported, without inferring ignored parameters from missing data.
- Vendor-neutral framing: the README documents the v2 mapping and recovery guarantees; no provider-specific template is built in.
